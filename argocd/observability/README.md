# Lab observability (OCP 4.19.11 home lab)

Written 2026-11-08. Metrics, logs, certificate expiry, tiered alerts and Grafana dashboards for the
home-lab cluster. The Argo CD Application `lab-observability` (openshift-gitops) reconciles
`apps/` from `main`.

**Status:** rendered and validated offline (kustomize; `promtool check rules`: 43 rules; `alloy fmt`;
`loki -verify-config`). Metric and label names were checked against the live cluster. All four
images passed Harbor's vulnerability policy. **Not yet applied by Argo CD.**

## What it covers

| Area | How | Alerts (severity) |
|---|---|---|
| Certificates | x509-certificate-exporter: every TLS Secret cluster-wide, kubelet PKI on every node, control-plane static-pod certs on masters. Kubelet TTL metrics | info: past normal rotation · warning: rotation overdue · critical: <3 d or expired. Explicit rules for the 14-day KCM bridge cert (expires 2026-11-21) |
| Workloads, every non-OpenShift namespace | kube-state-metrics, kubelet, cAdvisor (platform Prometheus) | crash loops, OOM kills, not ready, Pending >30 m, image pull or config errors, memory near limit, CPU throttling, replica mismatches, failed Jobs, PVC 80 % / 92 % / inodes |
| Kafka (Strimzi) | PodMonitor on the JMX exporter (bootstrap) | under-replicated (warning), offline partitions and controller count (critical) |
| GPU (Tesla P40) | DCGM exporter | temperature 80 °C / 88 °C, XID errors, framebuffer full, metrics missing |
| Control plane | platform metrics | control-plane kubelet unreachable, etcd below 3 members, etcd fsync p99 >2 s, KCM without a leader. These are the failures behind the 2026-11-08 outages |
| Logs | Loki 3.7.9 (72 h retention) and Alloy (API tailing, no privileges), app namespaces only | Loki or Alloy down, Loki discarding lines |

OpenShift's own rules still cover `openshift-*`, `kube-*` and `default`. These rules fill the
other namespaces and the lab-specific gaps.

**Dashboards** (Grafana → folder *lab*), generated by `apps/grafana/dashboards/generate.py`:
- Namespace overview and Pod detail: pick any namespace or pod. They include logs and events.
- Kafka, Harbor, PostgreSQL (egodeapp), GPU P40, Certificates, Control plane and etcd, Nodes,
  Alerts overview, obs-agent.

Dashboards are **templated per workload type** rather than one static dashboard per pod. There are
409 pods, and their names change on every rollout.

**Per group and per namespace** (Grafana → folder *namespaces*), from
`apps/grafana/dashboards/groups.yaml`. Every non-OpenShift namespace is listed once, either in a
**group** (namespaces serving one system share a dashboard, with a picker limited to the group) or
**isolated** (its own dashboard). Each one shows critical alerts needing immediate attention, containers
not running and why, CPU, memory, restarts, throttling, PVCs, error-log rate, logs and events.
`extra` adds panels for what runs there: `jvm` (heap, GC), `gpu` (DCGM, GPU holders), `stateful`
(PVC fill and 7-day full projection). `LabNamespaceWithoutDashboard` (info) fires for any namespace that
runs pods and is not listed. To add one, edit groups.yaml, run `python3 generate.py`, and commit.
Those dashboards are in their own ConfigMap because Argo CD's client-side apply caps an object at
256 KB. At about 15 KB each, around 17 entries fit before the ConfigMap must be split again.

## Not covered, stated

- **Harbor app metrics**: not enabled in its Helm values. Harbor gets pod, storage and log-derived signals.
- **PostgreSQL internals** (connections, locks, replication): no postgres_exporter, since it needs
  DB credentials. It gets pod, storage and log signals.
- **Logs from `openshift-*`**: not collected. Every tailed pod is a stream through the API server,
  and the only storage is NFS on the same slow datastore that caused the outages (platform issue 005).
  Widen `alloy.yaml` once etcd fsync is healthy.
- **Revisioned static-pod kubeconfigs** (`kube-controller-manager-pod-N`) are not watched: the
  exporter does not glob paths. The KCM client cert is covered through its Secret and its current
  on-disk copy.
- **Red Hat support**: the `openshift.io/cluster-monitoring` label on `lab-*` namespaces is not
  supported for non-OpenShift namespaces. It is used so rules can see every namespace.
- **Kafka metric names** follow Strimzi's example JMX rules. If `kafka-metrics-configmap` differs,
  `KafkaMetricsMissing` fires.

## Bootstrap (once, cluster admin on ocp-svc)

```sh
export KUBECONFIG=/root/ocp-install/auth/kubeconfig
cd platform-gitops/argocd/observability
# 1. SCC binding for the cert exporter, Kafka monitors, the lab-certs namespace (Argo CD cannot create these)
oc apply -f bootstrap/scc-and-app-monitors.yaml
# 2. Harbor pull secret into the new namespaces (images are in Harbor's private library project)
for ns in lab-certs lab-logging; do
  oc get ns $ns >/dev/null 2>&1 || oc create ns $ns
  oc -n obs-agent get secret harbor-pull -o json | jq --arg ns $ns '{apiVersion,kind,type,data,metadata:{name:.metadata.name,namespace:$ns}}' | oc apply -f -
done
# 3. Hand over to Argo CD
oc apply -f bootstrap/application.yaml
# 4. Alert routing (needs the webhook URL in a mode-600 file; Slack or Teams Workflows). Dry run, then --apply
bootstrap/alertmanager-route.sh --webhook-file /root/.teams-webhook
```

Grafana (`obs-grafana`) already exists. It was applied from AiChohort first, and Argo CD adopts it.
Its secrets `grafana-admin` and `harbor-pull` stay out of git.

## Change a dashboard or rule

Edit `apps/grafana/dashboards/generate.py` or `groups.yaml` (then run it), or `apps/rules/*.yaml`, open a PR, and merge.
Argo CD syncs from `main`. Validate rules with `promtool check rules` before merging.
